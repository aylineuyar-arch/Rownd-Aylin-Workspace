The serious one: `POST /archive-login` read `Content-Length` with no validation and passed it straight to `self.rfile.read(length)` — a negative value makes that call block until the connection closes, and since this is a plain single-threaded `HTTPServer`, that **freezes the entire server for every client**, not just the bad request. - **Replaced HTTP Basic Auth with a real session-cookie login — Basic Auth's native browser dialog turned out to be unreliable.** Watching the actual traffic in a real browser session, a single blocked page load produced over 30 identical requests to `/private-rfi-archive/`, all still returning the correct 401 — the server was fine, but the browser's own native Basic-Auth negotiation was retrying in a tight loop trying to resolve credentials, even with an explicit (wrong) `Authorization` header already attached, and the fetch sometimes failed outright instead of resolving. That's specifically caused by responding 401 with a `WWW-Authenticate` header, which is what tells a browser to attempt that native negotiation at all.
